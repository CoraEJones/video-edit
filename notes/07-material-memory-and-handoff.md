# 素材记忆与子任务：让短上下文使用大素材库

整理日期：2026-10-14。200段素材的信息保存在磁盘，不要求某个Agent长期记住整库。子任务也不能凭上一轮记忆承担交接。

## 四层信息各自存什么

| 层级 | 内容 | 使用方式 |
|---|---|---|
| 原件与清单 | 文件身份、哈希、探测信息、来源和许可 | 原件保护；不能由文件名推断画面 |
| 观察记录 | 源区间、联系表、密集帧、转录、质量与未知 | 证据按实际审看范围保存 |
| 索引与事实表 | 区间标签、故事用途、用户确认的关系和时间 | 有限检索，返回摘要与详情路径 |
| 当前上下文 | 制作单、故事方向、阶段状态、关键缺口、少量候选 | 只决定下一步，不充当完整数据库 |

相机时间和GPS需要真实元数据；文件创建时间、名称、目录位置不能冒充拍摄地点或时刻。资料缺失就保留未知，整理派生副本不会凭空补齐事实。

## 批次是工作范围，也是交接合同

通常每批8–12条，长转录或复杂动作再缩小；字符预算不是精确token数，还要给图片和工具返回留空间。使用少量工作者，完成一批再领取下一批；没有委派工具就由主助手串行领取，同样落盘。

SQLite事务与租约防止重复领取。过期租约可重领，旧工作者不能继续提交；过期不代表素材坏。子任务只拿分配编号、记录路径、相关需求和专属输出目录，不拿整个库，也不写最终计划或登记工程。

提交必须覆盖全部分配编号，带input_fingerprint、status、coverage和segments。实际观察、编辑解释和未知分开。不能看图就报blocked_visual；不能听音就保留audio_reviewed=false。工具检查编号、路径、范围和指纹，不证明模型确实看过。

```text
init → claim → packet → 实际审看并写submission → ingest → query → compile
追加精审：reopen → 新租约 → 新结果 → 核验并归档旧版
```

新结果写到submission，主助手核验后成为canonical结果；不能覆盖前版证据。重开期间暂时移出候选检索，防止修订中的观察被当最终结论。

## 检索要按故事缺口问

“人物动作后的反应”“建立环境的镜头”“安静收尾”“同一动作结果”比一次请求全部200条更有效。返回少量摘要，必要时打开区间详情与密集帧。没有已审候选时，元数据只能导航到待审素材，不能升级成画面事实。

主助手维护身份、地点、事件关系与用户事实表。跨批镜头的相似性不证明同一事件；最终选段记录segment_id，严格检查处于已审范围。必留瞬间检查完整源区间，而非只检查某个文件有没有出现。

## 缓存与恢复

输入身份、抽样、ASR设置和实际文件变化会影响分析与检索；故事改动重排候选，音乐改动复查映射与声音，标题改动主要影响图形、合成和视觉复核。复用前核对依赖指纹和输出文件，不能只因名字相同就用旧结果。

上下文压缩或新进程恢复后，先读制作单、workflow-state、memory status和故事摘要，再检索候选。没有落盘的内容不能叫已保存记忆。某个批次失败时保留已完成证据和未知项，缩批或由主助手接管，不无限重新派发。

当前已实现索引、租约、受限检索、精审重开和归档；200段规模有本机技术观测和实际分批使用记录。它不等于已证明模型上下文真正清空后的所有恢复情景，也不等于语义检索达到专家真值的召回率。
