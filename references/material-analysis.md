# 素材审看：先看见，再解释

在 `analyze` 完成后、写故事之前阅读本页。主助手可按素材分组把审看交给有视觉能力的子助手；没有子助手时由主助手完成同一合同。子助手只提交分析，不各自改总时间线。

## 已有输入与真实能力

读取 `request.json`、`inventory.json`、`analysis-report.json`。清单里的 `id` 是素材引用依据；`frames[]` 含 `path/time/brightness/sharpness`，`contact_sheets[]` 是带素材编号和源时码的联系表；`transcript[]` 含语句、起止时间和识别置信提醒。保留原清单，另外写 `material-analysis.json`；本页 sidecar 供助手决策，不是导出器自动执行的字段。

`analysis.py` 目前按时长均匀抽样，数量受配置上限限制，缩略图最长边为 640 像素。它不检测景别、情绪、失焦区间、抖动或故事，也不证明整个视频已经逐帧审看。`brightness` 和 `sharpness` 只用于定位可疑位置；高频纹理可能得高分，故意虚焦可能得低分，不能按单一分数淘汰素材。转录 `done` 只表示识别完成，重要原声还需试听。

## 审看流程

1. **通览全部成功分析的素材。** 实际打开所有联系表，先辨认大致场景、人物活动、可用声音与重复内容。图片直接看原图。文件名、文件夹和拍摄时间只作线索；地名、行程次序、人物身份要另外找证据。失败文件标为待检查，不默认列为废片。
2. **按内容拆源时间区间。** 一个文件可以从远景摇到特写、从清晰变失焦、从安静变热闹，不能用一个文件级标签覆盖全片。标记候选起止、动作阶段、景别变化和可疑区间。先覆盖，再按价值精看，不对数小时素材机械逐帧全部展开。
3. **为候选追加多帧。** 对可能使用的动作、表情、讲话、镜头边界，按 [密集取帧工具](frame-review-tool.md) 输出带源时码的相邻帧，再实际打开检查；也可在可用播放器中回看短片。一般动作可先以 0.5–1 秒间距补看；快速动作、疑似抖动、焦点跳动、遮挡和精确切点需要更密的帧序列或短片回放。保留入点前、入点、内部、出点前后证据；抽样稀疏时不能认定中间连续稳定。需要确认一帧切点时才逐帧检查该小段。取帧工具只生成证据，语义判断仍由实际看图的助手完成；不要发明四命令的额外参数。
4. **在足够分辨率下看质量。** 联系表用于导航；人脸、焦点、细节和裁切适配要打开对应原分辨率帧或原片核实。检查主体是否清楚、焦点是否来回寻找、运动模糊是否破坏信息、抖动是否令人不适、边缘遮挡/杂物是否抢主体、曝光和白平衡是否突变。画面暗不等于无效，主体不在中心不等于构图失败；先判断叙事用途。
5. **试听关键声音。** 按 [原声审核](original-audio.md) 默认静音，仅清楚的关键讲话或特别有故事价值的同期声可候选。区分说话、现场氛围、相机操作声、风噪和已录进原片的音乐；记录噪声、爆音、失真、语音可懂度、自然收尾与可作 J/L 衔接的区间。关键话语轻度清理后仍不清楚就静音，字幕只用核实内容。没有听音能力时标 audio_reviewed=false，不能放行原声，不把转录当作已经听到，也不凭静帧声称有海浪声。
6. **交付区间建议。** 输出推荐段、备选段、跳过段与原因，并记录真正看过/听过的证据。模糊、剧烈抖动或无用内容从候选时间线排除，**不删除、覆盖或移动原始文件**。罕见重要瞬间即使不完美也可保留短段并说明取舍；必留段质量不佳时先保留用户意图，使用其他画面承接或给出实际限制。

## 分析维度

| 维度 | 需要回答的问题 |
|---|---|
| 画面内容与动作 | 有什么主体，在做什么？动作的准备、进行、结果在哪里？哪些细节能让观众理解前因后果？看不清时写未知。 |
| 景别与构图 | 远/全/中/近/特写，是否随时间改变？主体位置、留白、视线、前后景、引导线与可裁切空间怎样？不能按分辨率猜景别。 |
| 镜头与运动 | 固定、推拉、摇移、跟随或手持？主体和相机分别向哪边运动？有无进出画、遮挡、相似形状/颜色可衔接下一镜头？ |
| 光色与质感 | 明暗、暖冷、主色/点缀色、对比、逆光、曝光突变；是柔和、粗粝还是清透？记录可放标题的相对稳定颜色区域，具体文字设计见 typography.md。 |
| 情绪与信息量 | 画面节奏、人物可见表情、距离和声音给人怎样的观感？紧张/轻松属于剪辑解释，不是人物内心事实；写出支撑线索与置信度。 |
| 技术质量 | 主体对焦、模糊类型、抖动程度、画面遮挡/杂乱、压缩与曝光问题，分别对应哪些时段？能否通过选择更短区间避免？不要默认有自动修复。 |
| 声音 | 完整讲话、笑声、环境层次、可用的声音桥、噪声与音量变化。增强音效需求单列，不能与现场实录混为一谈。 |
| 连续性与故事用途 | 可作开场、建立地点、动作、反应、细节、过渡、转折或收束吗？前后动作方向、地点、时间、光色是否连续？重复镜头是否真的增加新信息？ |
| 来源与不确定性 | 每个关键判断来自哪张帧/哪个时码/哪句用户描述？哪些只是解释，哪些尚待核实？用户说“第一次去”可作用户事实，画面里独自一人不能证明“第一次独自远行”。 |

## 子助手输入与交接

主助手给每个审看子助手：共同的 `request.json`、指定的真实素材 `id` 集合、清单/图像/音频路径、统一时码单位、本页合同及独立输出文件路径。按场景或数量分批，避免多名子助手改同一文件。子助手返回 `analysis-batches/<batch>.json`；主助手检查覆盖、源时长、证据文件存在与不确定项后合并。同一人物身份、地点名称和跨文件连续性由主助手统一核实。文件变动或指纹不匹配时复核该素材，不能直接复用旧结论。

所有区间采用源秒数 `[source_in, source_out)`，不是最终时间线秒数。建议字段如下；未看过用 `pending`，不为了让流程往下走填 `reviewed`。示例仅示意格式，真实任务替换编号、路径、时间和描述后才可作为证据。

```json
{
  "schema_version": "material-analysis-1.0",
  "inventory_path": "inventory.json",
  "time_basis": "source_seconds",
  "user_facts": [{"id": "fact-1", "text": "用户说这是一次周末出游", "source": "request.background"}],
  "assets": [{
    "id": "v_example",
    "status": "reviewed",
    "coverage": {
      "contact_sheets_viewed": ["frames/v_example/contact_1.jpg"],
      "frame_times_viewed": [2, 2.5, 3, 3.5, 4],
      "playback_ranges": [],
      "audio_reviewed": false,
      "limitations": ["尚未试听；抽样不能证明所有帧稳定"]
    },
    "segments": [{
      "segment_id": "v_example_s1", "source_in": 2, "source_out": 4,
      "observations": ["中景，一人向画面右侧行走", "蓝色水面占左上区域"],
      "shot_size": "medium", "camera_motion": "unknown", "subject_motion": "left_to_right",
      "light_color": {"exposure": "正常", "temperature": "偏冷", "palette": ["蓝", "灰"]},
      "interpretations": [{"text": "可表现安静的停留", "confidence": "medium", "basis": "画面留白和单一动作"}],
      "quality": {"subject_focus": "clear_in_viewed_frames", "shake": "unverified", "clutter": "low"},
      "audio": {"status": "not_listened", "speech_ranges": [], "ambience": []},
      "story_roles": ["transition", "breathing_space"],
      "decision": "candidate", "reason": "方向清楚，适合作两场景间的短过渡",
      "evidence": [{"kind": "frame", "path": "frames/v_example/extra_3.000.jpg", "time": 3}],
      "unknowns": ["具体地点", "人物心情"]
    }],
    "skip_ranges": [{"source_in": 0, "source_out": 1.5, "reason": "已查看帧中镜头被遮挡", "evidence_times": [0, 0.5, 1, 1.5]}]
  }]
}
```

`observations` 放直接可见/可听的内容，`interpretations` 放故事和情绪解释，`user_facts` 放用户明确提供的信息；三者不要互相替代。证据帧路径必须存在且确实查看过。无法判断的抖动、原声、地点或人物关系保留未知，后续故事仍可用已知信息推进。主助手把最终入选证据和未用原因摘要转入 `edit-plan.json` 的 `review`；不把整份 sidecar 塞进 `shots`。
