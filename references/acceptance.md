# 验收与故障

1. doctor：只要求当前选择的 Codex 或 DeepSeek Harness；MP4 路径不要求剪映与草稿库，聊天不要求图形窗口，转录/配音按需要检查。工程模式扫描剪映；仅有安装包不能算已安装。Skill 文件/版本与当前宿主真实加载分开报告；ready 不等于模型有视觉/试听能力或界面验收通过。
2. analyze：原始文件的大小/修改时间不变；联系表正确对应时间；有音频时转录成功或明确报告未识别；取消向导不创建分析任务。
3. validate：素材范围、连续主轨、帧对齐、字幕时序、必留内容、已审看证据均正确；未知高级效果直接报错。默认检查不降低分辨率或正常速度镜头的有效帧率；指定更小规格需记录用户要求。
4. export：MP4 路径核对所引用原件哈希，帧流直接到最终编码；工程路径额外检查完整原片副本哈希与原生材料路径、草稿加密回读、独立文字/声音/蒙版轨。MP4 完整解码并核对实际宽高/帧率、总帧数、音轨格式与时长；预览无损与 HDR 状态如实记录，见 [画质规则](quality.md)。
5. 界面验收（仅工程交付）：在剪映首页打开新建测试项目；播放并确认时间码/画面前进；实际修改一条字幕或片名；保存/退出工程后重新打开，确认修改保留。登记时备份首页索引，原有条目不变。录入 verification.json 的界面验收字段需要真实操作证据，不得仅根据结构填 true。MP4 用户不需要为此安装剪映。
6. 搬迁验收：复制新测试包到另一个工作区目录，relocate 后确认素材路径都在新包内，并确认刚刚的字幕修改仍在。跨目录通过不等于第二台电脑通过，报告中区分。
7. 初稿观感：人物未被不当裁切；字幕可读；讲话没有截词；配乐不过响；分屏和蒙版边界没有明显错误；结尾干净。
8. 流程证据：素材分段分析记录实际看过的图片/时码，故事各段可追溯到素材；未审区域不冒充全覆盖。子任务只写分配文件，主助手合并并检查必留内容。无视觉/无委派时的回退与限制如实记录。
9. 标题与声音：标题所在色块在首中尾可读、不遮主体，缺字回退已检查；配乐不是字母序误选，节拍有时间映射和试听状态。audio_layers 的区间/循环、重叠淡化、对白压低、原件哈希/许可随包核对；仅原声时没有额外库音。小数秒音轨在原生库与预览都能导出，搬迁后的计划引用包内原件。完整解码/峰值不等于真实听审。
10. 原声与叠层：正增益原声须有真实听审区间，变速原声为零；含噪关键话语轻清理后仍差则静音。静音字幕不压低音乐。艺术字检查字形、透明边缘和可读性；走马灯检查首/末帧位置及跨切点连续。最终视频帧数符合时间线，中间使用未压缩帧流或 FFV1，仅 MP4 最后一次有损编码；默认中文字幕，片头和结尾有不同于正文的节奏。
11. 需求接入：已知答案预填，只补问缺项/冲突；缺素材路径不能猜，输出建议须确认。检查用户真实确认及内容指纹，输出方式/位置一致；取消、缺项、未确认或关键需求改变时不能开工。确认“全部原声静音”“仅关键讲话”“不配音”“字体文字”后，计划不得反向执行。改片创建新版本，不覆盖旧工程。

剪映 11.5 的蒙版池是 materials.common_mask。固定草稿库写出的旧 masks 字段会被编辑器丢弃，导出层已转换。必须在编辑器保存后再次读取，确认蒙版仍存在；首次加密回读无法发现这种兼容性问题。[同类草稿实现的实际检查](https://github.com/Gusmares/MCP-CapCut#bundled-effect-catalog)。

剪映保存后会生成 Timelines/<ID>/draft_content.json；搬迁必须同时处理根草稿和所有当前时间线。不能只改根文件然后声称用户修改被保留。

搬迁时优先保留已有且可用的矩形资源路径；不要一律重绑到旧缓存。当前电脑的已验证路径可能与草稿库内置的旧资源编号不同。

常见返回：CANCELLED、DEPENDENCIES_MISSING、MISSING_MEDIA、SOURCE_CHANGED、SOURCE_OVERFLOW、REVIEW_REQUIRED、UNSUPPORTED_TECHNIQUE、NARRATION_TOO_LONG、CLOSE_JIANYING、OUTPUT_EXISTS、DRAFT_ALREADY_EXISTS。告诉用户可执行的下一步，不让用户分析堆栈。

导出中断保留 partial_output 和 failure.json，不修改原始素材，也不强制结束剪映。导出成功但未登记时交付工程位置，关闭剪映后可继续 relocate --register，无需重新转码。
