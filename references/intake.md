# 需求接入、补问与确认

两条入口共用 `intake.py`：自然语言对话，或大字向导。入口不决定交付方式；两者都能选择只要 MP4 或同时保留剪映工程。不能为了使用聊天入口而强制启动窗口。

## 先提取，再补问

先从当前请求和明确适用于本次项目的已确认上下文提取答案，写内部 `request.json`；不要让用户填写 JSON。不能把另一个项目的路径或偏好未经确认套进来。

`request-check --request REQUEST` 返回 `missing_fields`、`invalid_paths`、`invalid_fields`、`questions`、`summary_lines`。没有文件夹、路径不存在、文件夹无支持素材，或前后要求冲突时，先解决再开始。只读文件列表和环境检查可以先做，确认前不取帧、识别语音、制作时间线或渲染。

每轮集中问少量相关问题，提供推荐与“由助手推荐”。已知字段直接预填；可选项可在制作单中列明推荐，一并让用户确认，不能以“默认值”暗中代替答案。路径、交付和有冲突的选择必须明确。

| 内容 | 字段与填写规则 |
|---|---|
| 素材位置 | `media_dir`：实际可读素材文件夹的绝对路径；缺失必须追问或选择，不能扫描全盘猜一个 |
| 输出位置 | `output_dir`：用户确认的交付父目录；可建议，但建议不自动写成已确认答案；不能等于或位于素材目录内 |
| 交付方式 | `delivery_mode`：`mp4` / `editable`（MP4＋剪映工程） |
| 作品与故事 | `name`、`category`、`theme`、`context`；未知经历不编造，`context=""` 表示用户暂无补充 |
| 时长与节奏 | `target_seconds`（10–7200 秒，或 `null` 明确交给助手推荐）、`rhythm`、`aspect` |
| 字幕 | `subtitles` 布尔值；开启才问 `subtitle_language`，首选简体中文、其次中英双语 |
| 配音 | `voiceover` 布尔值；开启才问 `voice_gender`；声音能力按环境检查结果说明 |
| 音乐 | `music`：自动配乐 / 使用我自己的音乐 / 只保留原声；自选时要求有效 `music_file` |
| 内容取舍 | `must_keep`、`must_keep_files`；明确无指定时空字符串和空数组，不把缺字段当回答 |
| 文字 | `text_style`；`title_mode=art_preferred/fonts_only`。艺术字图片无法直接改字形内容，需先说明 |
| 原声 | `audio_policy=strict/key_speech_only/mute_all`；都不保留变速镜头原声 |
| 开头 | `opening_style=highlight_reveal/photo_carousel/story_based` |
| 结尾 | `ending_style=slow_echo/linger/story_based` |

`DEFAULTS` 是给助手/向导展示的推荐集合，不是自动补齐用户遗漏项的授权。通常推荐艺术字优先、严格原声审核、精彩快闪与黑幕、结尾慢下来呼应前文。配音关闭不需要追问音色；字幕关闭不必问语言；自动配乐不必问音乐文件路径。

字幕打开不等于必须识别语音：纯风景故事字幕可以来自已核实故事文案。需要逐句转录时明确 `transcription_required=true`，按需检查语音依赖；缺识别模型时不要把未转录的讲话说成已识别。

## 确认制作单

把 `summary_lines` 转成自然语言制作单，给用户看实际路径和完整方案。例如：

> 素材：你刚选择的海岛素材文件夹；输出：你确认的成片目录。只要 MP4，约两分钟，横屏电影感，中文字幕，不配音，音乐由助手选择。艺术标题优先；严格审核原声，变速静音。精彩快闪与黑幕开头，结尾慢下来呼应前文。无指定必留素材；作品名和故事主题采用上面列出的推荐。确认后开始。

真实制作单必须展开实际路径和具体推荐，不能把上面的泛称直接当最终确认。用户明确回复后才调用：

```text
python scripts/video_tool.py confirm-request --request JOB/request.json --user-confirmed
```

该命令记录确认方式、时间和内容指纹，不能制造用户同意。向导最后的确认按钮使用同一逻辑，不需要在对话里重复确认完全相同的制作单；如用户在向导取消，结束该次制作。

脚本在 `analyze`、`export-mp4`、`export-jianying` 执行前检查确认，输出模式及位置必须与制作单一致。资料变动导致指纹失效时重新展示变动后的制作单。未确认、缺路径、错误模式在创建制作目录前被拒绝。

`JOB` 是内部分析任务目录；不把 `analyze --output JOB` 偷换成用户的交付路径。最终交付在 `request.output_dir` 下创建新作品子目录，已存在则报错而不覆盖。

## 接续旧任务

旧版 `request` 缺字段或确认记录时可以读取、验证和整理已有计划；分析及重新导出前需补齐并确认。把完整确认对象复制到计划的 `request`，不能为让校验通过而手改目标时长、重新计算指纹或伪造确认。

原有 `review.status=reviewed` 是画面审看证据，和用户的制作确认不同，二者不能互相替代。导出成功也只代表技术验证通过，仍需审看、试听成片。
