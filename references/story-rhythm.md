# 从素材到故事，再到节奏

在完成 [素材审看](material-analysis.md) 后阅读本页；故事、音乐候选和粗剪需要相互修订。故事子助手消费分析 sidecar 和用户需求，输出 `story-outline.json` / `story.txt`。节奏子助手可提出区间与切点，主助手负责把实际可执行内容写入 [剪辑计划](plan-format.md)，检查全片连续性。

## 先找到这批素材的主线

用一句话回答“这部片子希望观众记住什么”。把素材按事件、地点、人物行动和情感呼应分组。旅行可以有多个城市、重复回访或非连续日期；家庭与活动片也不必套“出发—到达”。有明确行程时可顺叙，有真实呼应时可主题并置，信息不足时选择诚实的氛围小片。

最多给出两条有实际素材支撑的候选方向，并推荐其中一条；用户已选方向或说“你决定”就继续，不把每个剪辑判断变成新问题。一般的“起承转合”可这样落实：

| 叙事作用 | 在现有素材中找什么 |
|---|---|
| 起：邀请观众进入 | 一段有吸引力的真实动作、声音或细节；接环境镜头交代处境。悬念要能由后文兑现。 |
| 承：让体验具体起来 | 地点与人物的关系、活动的展开、远中近变化；每组镜头提供新信息，避免逐文件报流水账。 |
| 转：让前面的意义发生变化 | 真实的意外、发现、相聚、目标达成，或热闹到安静/陌生到熟悉的视觉与声音对比。没有冲突时不制造冲突。 |
| 合：让记忆停留 | 动作的结果、回望、告别、余音或呼应开头的细节；可用一个长一点的镜头，不必靠大段总结文案。 |

用户提供的巴黎故事示例用于学习“个人视角—具体见闻—变化—余韵”的组织方法，不能据此给所有作品填入巴黎、21 岁、第一次远行、错过飞机、戒备或和解。跨地点组接不能暗示两个无关人物在互相回应或两个事件有因果关系。日期/地点未经证实时用中性过渡，不写虚构地名卡。

故事不必有旁白。先写完整文案，再区分：配音稿、片名/章节、实际讲话字幕、仅交付用户阅读的文字。无配音时让镜头与经过严格审核的声音讲故事；不要把散文全部变成滚动字幕。抒情句可写主观感受，但不要替用户断言未确认的经历和内心。片头首选精彩片段快闪与揭题，结尾放慢呼应，具体见 [片头与结尾](opening-ending.md)，不把正文的匀速节奏铺满全片。

## 故事与节奏交接文件

`story-outline.json` 是助手工作文件，导出器不会自动读取这些字段。每一叙事段要引用分析中的真实 `segment_id` 与证据；`timeline_target` 是粗略分配，最终秒数由可用素材、动作和音频长度决定。推荐结构：

```json
{
  "schema_version": "story-outline-1.0",
  "analysis_path": "material-analysis.json",
  "premise": "在一段真实行程里，留住奔忙与停留的对照",
  "structure": "thematic_within_verified_chronology",
  "sections": [{
    "id": "section-1", "function": "opening", "timeline_target": [0, 8],
    "what_viewer_learns": "先看到一次行走，再看清周围环境",
    "segment_refs": ["v_example_s1", "v_other_s2"],
    "evidence_refs": ["v_example:3.0", "v_other:6.0"],
    "voiceover": null, "title": "在路上",
    "rhythm": {"energy": "low", "shot_seconds_hint": [2, 5], "protected_speech": []},
    "sound_intent": "原背景静音，让选好的音乐轻轻进入",
    "claims_to_verify": ["是否有特别有故事价值且清楚的现场声音"],
    "fallback": "没有合格原声则保持静音；后期库音须明确来源"
  }],
  "music": {"status": "candidate", "file": null, "beat_map": null, "listened": false},
  "gaps": [],
  "must_keep_resolution": []
}
```

以上是格式示例，不能直接当成真实剪辑结论。`must_keep_resolution` 记录用户必留内容分配到哪一段；`gaps` 记录素材欠缺及替代方案。故事子助手不能把审看未确认的内容升级为事实；主助手复核跨素材叙事后才收敛为一条主线。

## 粗剪：先看得懂，再磨切点

按故事挑选完整且不重复的动作、反应和环境段，安排连续主轨。每个入选区间要能说明“为什么在这里”。远景建立位置、中景说明行动、近景呈现细节是常用组合，不是每场都必须凑齐的三连镜头。避免为了补一个不存在的近景过度裁切损失画质。

先用直切把主线连通：观众是否知道人在做什么、场景为什么切换、片尾回应了什么？有动作就保留开始和结果；有讲话就优先保留完整语义。标记可缩放的过渡段和不能截断的语句/重要动作，为音乐留调整余地。缺少素材时缩短作品或用已存在的照片、原声承接，不循环同一镜头凑时长。

## 音乐在精剪前介入

用户选择“只保留原声”时跳过本节选曲/卡点与所有外加音效，用实际动作和现场声音安排节奏；不要以增强环境音为由绕过关闭选择。

故事方向确定后即挑音乐候选并试听，精剪锁定之前确认使用的文件/实际音频版本。依据内容选情绪、速度、段落起伏、乐器密度和有无人声；短片通常一首足够，多个故事阶段确有需要才换曲。强烈歌词、强鼓点未必适合讲话或安静的情绪高潮。

具体选曲、少量多曲编排、独立环境音轨和执行字段按 [声音设计](sound-design.md) 与 [计划接口](plan-format.md) 落实。助手根据故事审听后明确选择文件，不按文件名字母顺序取第一首。交付准确写出音乐来源，不把库曲说成用户创作；缺少可用库时可用现有程序伴奏并说明其简单循环听感。

现有 `sound.detect_beats` 对 **48 kHz、双声道、16-bit PCM WAV** 给出频谱起音候选；它是 Python 模块函数，不是新的四命令 CLI。导出产生的音乐分析也不会因 `techniques` 写了 `beat_cut` 自动挪切点。按声音设计文档准备实际使用的音频版本，取得候选节拍并试听后再精剪；也可先导出临时粗剪，从实际配乐分析回到剪辑计划。若更换、剪接或变速音乐，旧节拍映射作废，按实际播放版本重新核对。

不能把任意波形波峰当强拍。结合试听标注适合剪切的鼓点、乐句起止、段落变化和留白；仅算法得到的点标为候选。音乐存在裁切/循环/错时入场时，说明音频时间与时间线时间的映射；循环连接处尤其要复听。不会听/没有有效映射时保留叙事剪辑，不能声称精确卡点已完成。

## 精剪：动作、声音和信息密度一起调整

- **长度是起点，不是配额。** 行走、乘车等过渡可先试 1–3 秒；景色或有意义的互动可先试 5–8 秒。普通信息段超过约 15 秒时检查是否拖沓，但完整讲话、情感反应或持续动作可以更长。静态镜头长一点不等于慢动作，缩短镜头也不等于变速。
- **高潮依故事决定。** 活动的高能高潮可增加镜头密度、动作和反应，插入确有前文依据的短回闪；人物更多不是高潮公式。安静的相拥、等待或发现也可以是高潮，允许少镜头、长停留甚至撤掉音乐。紧张感需要真实内容支撑，不能把无关镜头剪成虚构事故。
- **先守住语义和动作，再靠近节拍。** 在可用入出点余量内把场景切换、动作落点或构图变化移到经过试听的拍点/乐句上。不必每拍换镜头。不可为踩点截断字词、动作结果，或伸入已确认失焦/剧抖的区间。片长固定且拍点不合时可换另一个合适镜头，不强拉所有速度。
- **张弛通过对比形成。** 慢—快—慢、动—静、远—近、原声—音乐、稀疏—密集可择一两种组织。高信息镜头给观众更多时间；短回闪需保证辨认得到，避免整段持续闪烁。重要脸部反应和台词不被装饰抢走。
- **剪口回看片段。** 实际看入点前后、出点前后以及相邻两镜头，核实焦点、抖动、运动方向、视线、空间和色调落差。保留能用的时间段；不要因为一个坏瞬间弃掉整条素材，也不要把前后不连续的动作描述成连续拍摄。

把节奏建议落到 `shots[].source_in/duration/speed/start`，按输出帧率对齐；素材出点仍为 `source_in + duration × speed`。调整镜头后联动标题、字幕、配音、章节、音频引入/延续和总时长，再运行 `validate`。节拍标记留在 sidecar 或实际 `music-analysis.json`，不向计划添加未支持的自动卡点字段。

## 技巧选择与后端边界

优先通过镜头关系完成转场：构图/颜色/形状相似切、同方向动作切、真实遮挡处切，通常只需要精确入出点。镜头原本没有遮挡就不能声称做出了遮挡转场。自然的声音提前或延续可用 `audio_lead/audio_tail`；设好来源和剩余长度，并实际试听。

现有 `fade_out` 是画面淡到黑，不能叫两镜头叠化。叠化、模糊转场、自动防抖、自动镜头匹配调色、追踪文字、复杂抠像和连续曲线变速不因写在故事建议里就获得执行能力。只采用已实现并验证的操作；其他建议记为可选后期处理，不冒充成片效果。分段恒速使用现有 `speed`，它不是光流慢动作或连续速度曲线。更多可用方法见 [剪辑技巧](editing-craft.md)。

完成精剪后再做局部标题、清楚的字幕和必要音效，最后同时复看有声版本与画面节奏。技术验收、可编辑工程和界面验证仍按 [验收标准](acceptance.md) 执行。

1.7的明确参数校正与20套创意LUT见 [调色接口](color-grading.md)，当前只支持MP4/预览；自动判断并修好所有镜头颜色仍未实现。
