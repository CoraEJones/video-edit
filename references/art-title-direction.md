# 艺术标题：从参考判断到实际画面验收

这是 `video-edit` 现有字体与颜色规范的补充。原有按画面取色、局部对比、字体缺字检查和安全边距规范继续适用。本文件把书法标题的造型选择、图层表达和验收落实到交付物，不允许仅在说明里写“已设计艺术字”。执行接口见 [标题引入API](title-intro-api.md)。

## 参考图能教什么

本次实际查看了用户提供的八张静态参考，其中一张为多例拼图，部分其他图为拼图中的单例扩展。它们显示的是造型与版式；静态图不能证明动画方式、入出场时间、配乐、音效或原工程实现。

| 参考观察 | 可以抽象的设计判断 | 不能直接照搬的东西 |
|---|---|---|
| 多例拼图分别使用淡紫细线、亮黄飞白、玫红手写、深绿墨迹、暖米白和亮青粗笔 | 同为书法标题，粗细、字势、色彩与结构可以明显不同。颜色需要在实际底片上成立 | 不能把参考的固定色号套到每段素材；玫红与亮黄也要查局部亮度 |
| 黄色干笔大字分两行错落，小英文与短线位于边角 | 主字承担情绪，辅助信息形成尺度反差；长收笔占据的是设计留白 | 不复制原句、作者水印、角落无关文案或整幅海报纹理 |
| 绿色插画海报使用白色竖排印刻字，小英文紧随，局部图案与题材有关 | 印刻字可成为独立家族；竖排、粗实字形和少量有语义的饰物可形成完整标题 | 不能挪用插画、电影标识或直接复制理发配件到不相关素材 |
| 深墨绿书法有干湿变化，两行位置错开，拖笔细长，微型英文与短线分散在留白处 | 不必把每个字排成同宽网格；长拖笔应向画面空处延伸，主副字有清楚层级 | 不因“书法自由”而接受错字、部件缺失、断裂不可辨 |
| 暖浅色手写主笔较粗，第二行缩进，局部有毛边、飞白与短英文 | 粗犷感来自起收笔与边缘，不需要满图颗粒；两行可以建立方向和轻重 | 不用粗黑描边把所有背景差异抹平 |
| 高饱和青色大横题置于暗海天，字中大小变化明显，末笔长扫 | 鲜艳色在合适的暗背景上可以成立；字内轻重、长短本身是构图手段 | 亮青落到白浪上可能失效；不能以整幅平均亮度证明可读 |
| 暖米白两行标题有大字与小字、对角长笔和足够天空留白 | 主字可以大、辅助字可以小，笔势可建立对角线；画面人物仍应完整 | 原图的小人物并不表示任何视频都可把人缩小或盖住动作 |
| 粉色窄竖题旁有小英文，另一个横向画面版本重组主副信息 | 同一文案可按画幅和主体位置改成竖排或横排；小字是层级辅助 | 不复制宣传日期、片方名称、未理解的外语文字或符号作“装饰” |

只保存抽象判断、原创提示词和自己的成果。用户参考图片、原片、标识、水印及来源中无授权素材不得随公开 Skill 包发布。

## 先决定字形，再决定参数

开始生成前，实际查看标题区间的首、中、尾与主体运动峰值。先确认文案能由画面支撑，再为每例记录：

- **字形家族**：飞白行书、细线手写、粗犷实笔、方整印刻/碑意，或其他有明确笔画特征的方向。不能把二十张同骨架字图仅换颜色后叫作二十种设计。
- **层级**：哪一个字/词为主、哪一个为辅。用字号、字距、两行错位、竖排、留白或收笔建立主次；不同时堆用所有手法。
- **实际字形位置**：先画出目标 painted-alpha bbox，再由原 PNG 的 alpha bbox 反算整张 PNG 的位置与缩放。透明留白不等于字形；PNG 可以越出画布，但实际笔画和配件不能因此被裁断。
- **配色**：从标题将出现的实际区域提取 2–4 个主辅色，记录色值是直接采样还是为对比调整。浅色区可用深墨，暗区可用暖白/浅色，已有鲜艳色可少量呼应。颜色在一次显现期间保持稳定。
- **配件**：默认零到两件，尺寸与面积弱于主字。短线、未闭合弧、少量墨点、小方章、英文短句都应有构图用途；不能每例机械加同一个红章。英文必须有意义且拼写核实，印章不能伪造人名、作者签名或未经确认的地名。

小配件如果直接画在同一张 PNG 里，其位置与字形一起被烘焙；如果需要不同入场、独立移动或删改，应生成为单独透明素材并保留独立图层。不能在报告中把图片内配件描述成原生可编辑对象。

## 主题、字组和尺度

先把可见事实和创作联想分开：手正在编织、列车驶过、咖啡落入杯中是画面依据；“慢下来”“去远方”可以是标题的创作方向，不能扩写成素材没有证明的亲身经历。先拟少量准确短句，再决定哪个词承担视觉重心。主题不是给每段强加同一条人生感悟；同一主题可由自然、手作、城市、动作等不同画面侧面承接。

两字题名只是其中一种结构。可设计短题＋小副题、两行长短句、单个大字＋其余小字、窄竖题＋横向注释等。在画布上先标主体与运动区域，然后指定主字目标高度、辅字比例、字组间距与收笔方向。主字大约占画高20–35%、辅字为主字40–65%可作小样起点；细线或低分辨率时应加大，不作为跨画幅硬阈值。最终以实际字形alpha和最终像素辨读为准。英文短句只是可选信息，不为了装饰强加。

例如手工器物的素材可用“慢慢／成器”：大“成器”承担形状，小“慢慢”作为独立字层；角落小方框呼应器物结构。咖啡可以用“一杯／慢时光”：主副字错落，暖浅色与咖啡棕来自实际杯体和液体色区。它们是原创构思示例，不是自动套用文案；每例仍需看底片、检查词义和生成字形。要独立显现，分别生成每个字组，不把整幅有复杂背景的海报当作透明标题。

提示词用明确可见特征替代单独一个“书法”标签：准确文字及行序、主辅字相对大小、粗细/干湿/飞白、方整或流动骨架、重心和长收笔、目标颜色、真实透明背景、不含额外印文。细线手写、粗实干笔、方整印刻、窄竖手写与疏朗行书应在总览里看出差异；不能仅把提示词中的书体名换掉。

运动的主次也应分层：主字先稳定，副字随后轻入；细线/点阵最后出现；或辅助引导线先指向留白再出现主字。三次曲线路径可以引导字组进入静止位置，旋转回落可以只作用于小配件。每段只选服务字势的少量动作，并保留足够静止阅读时间。不要把所有字、线、章一起做同幅度的滑入和缩放。

## 生图和像素边界

有图像生成能力时，短标题优先使用真实生成的透明字图。提示词包括准确文案、字形结构、笔触干湿、主辅色和留白方向；只给必要的短字，不让生成器填充不必要的英文、日期或无意义印文。保留工具输出的原始文件与来源记录，原件不裁、不改、不覆盖。

逐字检查中文笔画与部件。识别模型或脚本检测不能取代人工辨字；书法允许变形，仍需在最终视频分辨率与实际背景上辨认文案。字形失败时做一次有针对性的修正；还不满意就明确回退到经过字形覆盖检查的字体排版，不把失败图宣称成功。

检查 alpha 是否真实存在、边框/四角是否透明、painted bbox 是否完整。黑色查看器底色不等于 PNG 有黑底；用 alpha 数据与实际背景合成判断。暗墨在黑底上不可见也不证明字图失败。反过来，有 RGBA 通道但整幅 alpha 都不透明，也不能当作透明字图。

带白边、脏底、大片半透明雾、残留矩形的风险，必须在实际明暗背景上观察。透明边缘统计只能提醒风险，不能单独判断白色边缘是预期墨色还是抠图残留。合成预览不能冒充生图原件，也不得默默修改原图后丢弃来源。

普通 PNG 的 sRGB、上游已显式转换的 BT.709 RGB 和来源未知的 RGB 必须区分；数值对比记录使用的传递函数与声明。不能将 BT.601 矩阵误当原色色域，不能根据“看起来不错”声称 Log/HDR 已正确转换。

## 字势怎样变成时间参数

运动服务于字势和画面。静态参考只用于方向设计，不写“复刻了参考动画”。

| 字形/画面判断 | 可真实执行的引入 | 需要保留的边界 |
|---|---|---|
| 横向长收笔、主体向右运动 | 很小的顺势平移与淡入，稍晚稳定；先于关键动作退出 | 大幅滑行会抢镜并使细笔画模糊，不能为动而动 |
| 细线、安静水面或夜空 | 缓慢淡入或极轻缩放，稳定停留时间足够读完 | 极轻缩放也要查最终像素中的细线，不假称光流或真实运笔 |
| 两行主次错落 | 两个独立词层错时出现，主词先/重，辅词后/轻 | 一张整句 PNG 只有一层，不能宣称已经逐字错时 |
| 印刻、碑意、手工题材 | 短而克制的显现，稳定停留，微小配件独立随后出现 | 不默认加震屏/砸落/盖章音，未配音则没有声音效果 |
| 下方主体动作密集、上方空区稍后被占用 | 标题提前退出，给主体让位 | 不为了固定四秒模板持续遮住列车、脸、手或浪上运动者 |

真实手写描边需要路径、逐笔蒙版或可核验的分层动画资产；普通透明 PNG 淡入、整幅矩形揭幕不等于逐笔书写。当前接口没有真实支持的效果，必须标为未实现、替代方案或已烘焙素材。

运动记录至少包含每层 `start_s/end_s`、入出场时长、位移像素、缩放、透明度和缓动。输出项目帧率、源时间与时间线时间各自有单位；不把整图左上坐标直接传成剪映归一化中心位置。

标题引入流水线还提供以下明确参数。它们是可计算的动画设计，不是从静态参考还原出的原动画，也没有承诺与剪映原生曲线控件的显示完全等价：

- `curved_path` 使用四个 `cubic_bezier_points_px=[[dx,dy],...]`，单位为相对 PNG 静止位置的画布像素偏移；第四点须为 `[0,0]`。入场进度经 `linear` 或 `smoothstep` 后代入真实三次贝塞尔公式，不是四点折线。
- `rotate_settle` 使用 `from_rotation_deg` 到 `rotation_deg`，正角顺时针、负角逆时针；任何已支持运动都可附带这两个角度。`rotation_keyframes=[{time_s,rotation_deg},...]` 可覆写自动角度，局部时间从零开始且落在项目帧上。
- `pivot_px=[canvas_x,canvas_y]` 指明旋转/缩放中心，默认取实际 alpha 字形 bbox 中心。整张 PNG 的透明留白大时，必须补偿位移，避免字形绕空白角落漂移。
- `settle_s` 是入场后回到静止位置的秒数。`overshoot_px` 与 `overshoot_rotation_deg` 是有界的位置/角度超越，必须有正 `settle_s`；本例接口位置最多24像素。它没有实现物理弹簧，也不是自动运动追踪。
- 每层 `motion-table.json` 保留逻辑路径偏移、实际传给原生全画布 PNG 的补偿偏移、缩放、角度和透明度。代码与工程共用逐项目帧样本；原生工程写逐帧线性关键帧，不能冒称已经写入原生贝塞尔控制柄。

非对称像素样本可以测试顺时针方向、中心补偿、曲线中点和 alpha；实际加密工程回读可以核对数值。两者都不能取代剪映内打开、播放、编辑、保存后的视觉检查，未完成时保留 `ui_verified=false`。

## 二十例的多样性检查

多样性针对这类探索实验，不强迫同一部连贯短片随意换风格。提交二十例时同时制作一张以同等尺寸展示的总览表，检查以下方面：

1. 至少覆盖飞白、细线/轻手写、粗实行笔、印刻/结构字四个清楚家族。最终以图形可见差别判断，提示词写了不同名字不算通过。
2. 包含横排、两行错落、竖排、主字大/辅字小等不同结构。只移动整块同规格两字标题到左右角，不能算充分的版式探索。
3. 至少使用深墨、暖浅色和有场景依据的鲜艳/中彩色方向；不为了凑数量牺牲局部对比。记录每组取色依据，不能全部米白字加同一红印章。
4. 长拖笔、疏密、大小关系和小配件均需有变化；某些例子保持无配件是合理设计。饰物不可比字更醒目，也不能盖住小主体。
5. 在已支持能力内至少探索三种明确的引入节奏/运动关系，例如顺势小移、静态淡入、独立词层错时。只有改相同平移动画的方向、速度，不应夸成很多种动画技术。

这是一张人工审看清单，不合成一个“审美分”。同一书体可以服务多例，前提是字形层级、场景配色和构图有实际依据。

## 必须形成的逐例验收证据

`title-design.json` 或本项目同义设计记录必须包含源 id/哈希、准确文案、生图原件/哈希、书体与布局理由、实际取色区域、色值来源、完整 PNG transform、painted bbox、安全边距、人工保护矩形、独立配件图层以及实际审看的时间和图片。

对每例至少审看：入场尚可读的第一帧、完全稳定帧、退场前最后可读帧、主体位置或局部背景变化最大的帧。只查完全透明的首尾不能证明文字可读。标题出现期间若有源内切景，在每个切景两侧重新审看；必要时改窗口、缩短显现或换源。

- 人脸、手部、工具、动作路径与关键物体采用**显式人工保护矩形**，按源秒记录。不能假称有人脸分割/跟踪；矩形只是保守提醒，仍应看实际画面。
- 安全边距与越界按实际 painted alpha 测量，透明 PNG 外框不用作碰撞框；反过来细拖笔、散落墨点和配件也必须纳入。
- 对比在实际 alpha 覆盖的背景像素上计算，分开检查大实笔与细线/飞白，不能用整幅画面均值或固定中部色块代替。
- 对比阈值、细线形态统计、画面颜色数量和数字标志均只辅助审看。它们不能证明汉字正确、笔势优美、层级清楚、题材适合或饰物不过量。
- 独立审看者实际看到合成/最终输出后，才能把 `human_visual_review` 从 `pending` 改成通过或需修正。代码跑通、原生工程结构可读、缩略图存在，都不等于视觉验收完成。

最终交付应能看到：二十段真实底片上的引入视频、透明标题原件、配件原件、同尺寸总览、逐例设计依据与验收结果。原生工程说明文字图片的可编辑边界：位置/缩放/透明度/时间可编辑，图内汉字形状须重新生成或替换原生文字，不能称为可直接改文案的字体。
